ఈ అప్లికేషన్‌ను మీరు ఎక్కడా కాపీ చేయకుండా, సొంతంగా Scratch (మొదటి నుండి) రాయాలి అంటే ఒక పద్ధతి ప్రకారం (Step-by-Step) వెళ్ళాలి. 
కోడింగ్ చేసేటప్పుడు ఎప్పుడూ మొత్తం కోడ్ ఒకేసారి రాయకూడదు. 
చిన్న చిన్న ముక్కలుగా రాస్తూ, రన్ చేస్తూ బిల్డ్ చేయాలి.
మీరు ఫాలో అవ్వాల్సిన 7 సింపుల్ స్టెప్స్ ఇక్కడ ఉన్నాయి:

📅 Step 1: Project Setup & Initialization (బిల్డింగ్ పునాది)

మొదట మీ కంప్యూటర్ లో ఒక ఫోల్డర్ క్రియేట్ చేసి సర్వర్ రన్ అవ్వడానికి కావాల్సిన ప్యాకేజీలు ఇన్‌స్టాల్ చేసుకోవాలి.
ఒక కొత్త ఫోల్డర్ క్రియేట్ చేయండి: mkdir task-manager-api మరియు అందులోకి వెళ్ళండి cd task-manager-api.
Node.js ప్రాజెక్ట్ స్టార్ట్ చేయండి: npm init -y (ఇది package.json ఫైల్‌ని ఇస్తుంది).
కావాల్సిన ప్యాకేజీలను ఇన్‌స్టాల్ చేయండి:

npm install express mongoose dotenv cors jsonwebtoken bcryptjs

డెవలప్‌మెంట్ కోసం nodemon ఇన్‌స్టాల్ చేయండి (కోడ్ మార్చిన ప్రతిసారీ సర్వర్ ఆటోమేటిక్‌గా రీస్టార్ట్ అవుతుంది):

npm install --save-dev nodemon

server.js మరియు ఒక సీక్రెట్ ఫైల్ .env క్రియేట్ చేయండి.


🌐 Step 2: Basic Express Server Setup (సింపుల్ సర్వర్ టెస్టింగ్)
మొదట సర్వర్ అసలు పనిచేస్తుందో లేదో చెక్ చేయడానికి బేసిక్ కోడ్ రాయాలి.
server.js లో express, cors ఇంపోర్ట్ చేయండి.
app.use(express.json()) మరియు app.use(cors()) మిడిల్‌వేర్ యాడ్ చేయండి.
ఒక సింపుల్ టెస్ట్ రూట్ రాయండి:
app.get('/api/test', (req, res) => res.json({ message: "Working!" }));

app.listen(5000) పెట్టి సర్వర్ రన్ చేయండి 
(npx nodemon server.js). 

బ్రౌజర్‌లో లేదా Postman లో http://localhost:5000/api/test ఓపెన్ చేసి చూడండి.


🗄️ Step 3: Environment Variables & Database Connection (డేటాబేస్ లింక్)
ఇప్పుడు మన సర్వర్‌ని MongoDB డేటాబేస్‌తో కనెక్ట్ చేయాలి.
.env ఫైల్‌లో మీ MONGO_URI మరియు JWT_SECRET కీస్ దాచండి.
server.js లో dotenv.config() యాడ్ చేయండి.
mongoose.connect() ఉపయోగించి ఒక connectDB ఫంక్షన్ రాసి, సర్వర్ స్టార్ట్ అయ్యే ముందే డేటాబేస్ కనెక్ట్ అయ్యేలా సెటప్ చేయండి.


👤 Step 4: User Model & Auth Controllers (సైన్-అప్ & లాగిన్)
యూజర్లు రిజిస్టర్ అవ్వడానికి మరియు లాగిన్ అవ్వడానికి లాజిక్ రాయాలి.
User Schema క్రియేట్ చేయండి (name, email, password fields తో).
పాస్‌వర్డ్ సేవ్ అయ్యే ముందే హ్యాష్ (Encrypt) అవ్వడానికి UserSchema.pre('save', ...) మిడిల్‌వేర్ రాయండి.

Register Route (/api/auth/register): 
యూజర్ డేటా తీసుకుని, ఈమెయిల్ ఆల్రెడీ ఉందో లేదో చెక్ చేసి, User.create() ద్వారా దాచండి. 
సక్సెస్ అయితే jwt.sign() తో ఒక టోకెన్ రిటర్న్ చేయండి.
Login Route (/api/auth/login): ఈమెయిల్, పాస్‌వర్డ్ తీసుకుని, bcrypt.compare() తో చెక్ చేసి, కరెక్ట్ అయితే టోకెన్ ఇవ్వండి.

టెస్టింగ్: Postman ఓపెన్ చేసి కొత్త యూజర్‌ని రిజిస్టర్ చేసి, లాగిన్ చేసి చూడండి. 
మీకు ఒక లాంగ్ token స్ట్రింగ్ వస్తుంది.


🛡️ Step 5: Auth Middleware - The Security Guard (సెక్యూరిటీ గార్డ్)టాస్క్‌లు క్రియేట్ చేసే ముందు, 
వచ్చే రిక్వెస్ట్ జెన్యూన్ యూజర్ నుంచే వస్తుందా లేదా అని చెక్ చేసే గార్డ్‌ని తయారుచేయాలి.
protect అనే ఒక మిడిల్‌వేర్ ఫంక్షన్ రాయండి.
ఇది రిక్వెస్ట్ యొక్క req.headers.authorization లో Bearer <token> ఉందో లేదో చూస్తుంది.
టోకెన్ ఉంటే, jwt.verify() తో దాన్ని డీకోడ్ చేసి, ఆ టోకెన్ లో ఉన్న యూజర్ ఐడి ద్వారా డేటాబేస్ నుండి యూజర్ వివరాలు తెచ్చి req.user లో దాస్తుంది.
అంతా కరెక్ట్ అయితే next() అని పిలిచి లోపలికి పంపుతుంది.

📝 Step 6: Task Model & CRUD Controllers (చేయాల్సిన పనుల లాజిక్)ఇప్పుడు అసలైన టాస్క్ మేనేజ్‌మెంట్ లాజిక్ రాయాలి.
Task Schema క్రియేట్ చేయండి. ఇందులో ముఖ్యంగా user: mongoose.Schema.Types.ObjectId పెట్టి ref: 'User' ఇవ్వాలి. 
దీనివల్ల ఏ టాస్క్ ఏ యూజర్‌దో ట్రాక్ చేయవచ్చు.

Create Task: req.body నుండి టైటిల్, డిస్క్రిప్షన్ తీసుకుని, req.user.id ని ఓనర్‌గా పెట్టి టాస్క్ సేవ్ చేయండి.

Get Tasks: Task.find({ user: req.user.id }) అని రాయండి. 
దీనివల్ల లాగిన్ అయిన యూజర్ టాస్క్‌లు మాత్రమే కనిపిస్తాయి.
Update & Delete: టాస్క్ ఐడిని బట్టి తెచ్చి (Task.findById), ఆ టాస్క్ యొక్క ఓనర్ ఐడి (task.user.toString()) 
మరియు ప్రస్తుత లాగిన్ ఐడి (req.user.id) సేమ్ అయితేనే అప్‌డేట్ లేదా డిలీట్ అయ్యేలా కండిషన్ రాయండి.



🛣️ Step 7: Express Router & Global Error Handling (రూట్లు సర్దడం & ఎర్రర్స్ ఆపడం)చివరిగా కోడ్ అంతా క్లీన్‌గా సర్దాలి.

express.Router() ఉపయోగించి ఆథెంటికేషన్ రూట్లను (/api/auth), టాస్క్ రూట్లను (/api/tasks) విడివిడిగా గ్రూప్ చేయండి.
టాస్క్ రూట్లకు పైన మనం క్రియేట్ చేసిన protect మిడిల్‌వేర్‌ని అప్లై చేయండి.
అప్లికేషన్‌లో ఎక్కడైనా అనుకోకుండా ఎర్రర్ వస్తే సర్వర్ క్రాష్ అవ్వకుండా ఉండటానికి app.use((err, req, res, next) => ...) 
అనే గ్లోబల్ ఎర్రర్ హ్యాండ్లర్ రాయండి.💡 మీ కోసం ఒక చిన్న ప్రో-టిప్ (Pro-Tip):మీరు సొంతంగా రాసేటప్పుడు కోడ్ మొత్తాన్ని ఒకే server.js ఫైల్‌లో రాయకండి. 

రియల్ వరల్డ్ లో ప్రాజెక్ట్ ఫోల్డర్ స్ట్రక్చర్ ఇలా ఉంటుంది. 
మొదట ఒక ఫోల్డర్ క్రియేట్ చేసి ఇలా విడదీసి రాయడానికి ట్రై చేయండి, ఇంకా ఈజీగా గుర్తుంటుంది:
📁 config/ -> డేటాబేస్ కనెక్షన్ కోడ్ (db.js)
📁 models/ -> యూజర్, టాస్క్ స్కీమాలు (userModel.js, taskModel.js)
📁 controllers/ -> లాగిన్, టాస్క్ ఫంక్షన్ల లాజిక్ (authController.js, taskController.js)
📁 middleware/ -> సెక్యూరిటీ గార్డ్ కోడ్ (authMiddleware.js)
📁 routes/ -> కేవలం అడ్రస్‌లు మాత్రమే (authRoutes.js, taskRoutes.js)
📄 server.js -> మెయిన్ గేట్ వే (అన్నిటినీ లింక్ చేసే చోటు)

మొదట Step 1 & Step 2 ఈ రోజే ట్రై చేయండి, సర్వర్ రన్ అయ్యాక ఒక్కో స్టెప్ బిల్డ్ చేసుకుంటూ వెళ్ళండి!
